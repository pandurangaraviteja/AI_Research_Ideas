25 research directions

Each is scoped to be tractable and defensible: a clear gap, a concrete method, a measurable baseline, and known ground truth or a published guarantee to lean on. They're grouped by the three units so you can pair a project with what you're currently studying.

Reality check: no idea is automatically "novel" or "bulletproof" — before committing, run a literature scan (Google Scholar, arXiv, Semantic Scholar) on the title keywords to confirm the gap is still open, and scope the experiment to compute you actually have. Defensibility here comes from clean baselines and reproducibility, not from a guarantee of a positive result.

①The gap

Hand-designed heuristics for $A^*$ (Manhattan distance, pattern databases) are admissible but often loose, so $A^*$ expands far more nodes than necessary. Learned heuristics are tighter but lose the admissibility guarantee, so optimality is no longer certified. The open question: can a learned heuristic stay provably admissible while being tighter than the hand-designed base?

②Mathematical foundation

$A^*$ orders the frontier by $f(n)=g(n)+h(n)$ and returns an optimal path whenever $h$ is admissible, i.e. $h(n)\le h^*(n)$ for all $n$, where $h^*$ is the true cost-to-go.

$$ h_{\max}(n)=\max_i h_i(n) \quad\text{is admissible if every } h_i \text{ is.}$$The pointwise max of admissible heuristics is admissible and dominates each — this is the safety anchor.

Train a GNN $\hat h_\theta(n)$ with an asymmetric loss that punishes overestimation heavily ($\rho\gg1$):

$$ \mathcal{L}(\theta)=\mathbb{E}\!\left[\rho\,\big(\max(0,\hat h_\theta-h^*)\big)^2+\big(\max(0,h^*-\hat h_\theta)\big)^2\right] $$

At inference, clamp to guarantee admissibility regardless of network error: $h(n)=\min\!\big(\hat h_\theta(n),\,h_{\max}(n)\big)$ is $\le h_{\max}\le h^*$, hence admissible — yet tighter than $h_{\max}$ wherever the network is confident.

③Method

  1. Pick a domain with computable $h^*$ on small instances (15-puzzle, grid pathfinding).
  2. Generate training pairs $(n,h^*(n))$ by reverse BFS from goals.
  3. Encode states as graphs; train $\hat h_\theta$ with the asymmetric loss.
  4. Wrap with the min-clamp; run $A^*$ and log node expansions.

④Plan of action

WK 1–2Baselines. Implement $A^*$ + Manhattan / PDB; record expansions on a benchmark set.
WK 3–5Train. Build the GNN, generate labels, tune $\rho$.
WK 6–7Integrate + verify admissibility empirically (no expanded node has $h>h^*$).
WK 8Analyze + write up expansion reduction with confidence intervals.

⑤Requisites

Background
$A^*$, admissibility/consistency, basic GNNs (message passing).
Tools
Python, PyTorch + PyTorch Geometric, NetworkX.
Data
Self-generated puzzle/grid instances with reverse-BFS labels.

⑥Evaluation

Baselines: Manhattan, pattern DB, raw (unclamped) learned heuristic. Metrics: mean node expansions, time-to-solution, % optimal solutions (must be 100%), admissibility violations (must be 0).

⑦What you can claim

A heuristic that is certified optimal (by construction) and empirically reduces expansions versus the admissible baseline. The claim is safe even if the network is mediocre, because the clamp protects optimality.

①The gap

Simulated annealing's performance is dominated by its cooling schedule and restart policy, which are usually fixed by trial-and-error. A schedule good for one instance is bad for another. Can an agent adapt the schedule online, per instance, with no prior tuning?

②Mathematical foundation

SA accepts a worse move of energy gap $\Delta E>0$ with probability

$$ P(\text{accept})=\exp\!\left(-\frac{\Delta E}{T}\right),\qquad T_{k+1}=\alpha\,T_k,\ \ 0<\alpha<1. $$

Treat each candidate schedule (a choice of $\alpha$, reheating threshold, restart trigger) as an arm of a multi-armed bandit. Select arms by UCB1:

$$ a_t=\arg\max_a\ \hat\mu_a+\sqrt{\tfrac{2\ln t}{N_a}} $$$\hat\mu_a$ = average reward (negative best-cost-so-far) of arm $a$; $N_a$ = times pulled.

③Method

  1. Define an arm set spanning cooling rates and restart rules.
  2. Run SA in epochs; each epoch the bandit picks an arm and SA runs under it.
  3. Reward = improvement in best objective; update UCB statistics.

④Plan of action

WK 1–2Vanilla SA on TSP + MAX-SAT; tune a fixed geometric baseline.
WK 3–4Add the bandit controller; define arms and reward.
WK 5–6Benchmark at fixed evaluation budgets, many seeds.

⑤Requisites

Background
Metropolis criterion, multi-armed bandits / UCB.
Tools
Python; TSPLIB, SATLIB instances.
Data
Standard TSP / MAX-SAT benchmark suites.

⑥Evaluation

Baselines: best fixed geometric schedule, random schedule. Metrics: final objective at fixed budget, anytime curves, win-rate across instances (Wilcoxon signed-rank test).

⑦What you can claim

A tuning-free SA that matches or beats a hand-tuned schedule. Even parity is a positive result (removes manual tuning).

①The gap

Memetic algorithms (GA + local search) work well but the choice of which operator to apply when is fixed. A learned policy could adapt operator use to the search state.

②Mathematical foundation

GA evolves a population to maximize fitness $\mathcal{F}$. Model operator choice as an MDP: state $s$ = population statistics (best/mean fitness, diversity $D=\frac{1}{|P|^2}\sum_{i,j}d(x_i,x_j)$), action $a$ = operator, reward $r$ = fitness gain. Learn $Q(s,a)$ by

$$ Q(s,a)\leftarrow Q(s,a)+\eta\big[r+\gamma\max_{a'}Q(s',a')-Q(s,a)\big]. $$

③Method

  1. Define operator pool (uniform/2-point crossover, mutation rates, a local-search step).
  2. Each generation: featurize state, choose operator via $\epsilon$-greedy $Q$, apply, observe reward.
  3. Train across many instances so the policy generalizes.

④Plan of action

WK 1–2Fixed memetic GA baseline on a chosen combinatorial problem.
WK 3–5Add tabular/linear $Q$ operator selector; define state features.
WK 6–7Ablate vs random and fixed operator schedules.

⑤Requisites

Background
Genetic algorithms, Q-learning, MDP basics.
Tools
Python (DEAP), NumPy.
Data
Knapsack / TSP instance generators.

⑥Evaluation

Baselines: fixed operator schedule, uniform-random operator. Metrics: best fitness at equal evaluation budget; convergence speed; operator-usage analysis.

⑦What you can claim

Evidence that learned operator scheduling improves sample efficiency, with an interpretable account of which operators the policy favors and when.

①The gap

$A^*$ is optimal but memory-hungry ($O(b^d)$ stored nodes); iterative-deepening $A^*$ (IDA*) uses linear memory but re-expands nodes. Where exactly does one beat the other under realistic memory caps? The literature lacks a clean cross-domain map.

②Mathematical foundation

For branching factor $b$ and depth $d$, $A^*$ stores $\Theta(b^d)$ nodes; IDA* performs iterated bounded DFS whose total expansions are

$$ N_{\text{IDA}^*}=\sum_{k=0}^{d} (b^{k})\ \approx\ \frac{b^{d+1}}{b-1}\quad(\text{re-expansion overhead } \tfrac{b}{b-1}). $$

Define the crossover memory cap $M^*$ as the cap below which IDA*'s extra time is worth the memory saved. The study estimates $M^*$ as a function of $(b,d,\text{heuristic error})$ empirically.

③Method

  1. Instrument both solvers to log peak memory + expansions.
  2. Sweep problem families (puzzles, grids, planning) and memory caps.
  3. Fit the boundary surface $M^*(b,d,\epsilon)$.

④Plan of action

WK 1–3Build harness + both solvers with telemetry.
WK 4–6Run sweeps across domains and caps.
WK 7–8Fit + visualize the frontier; report with CIs.

⑤Requisites

$A^*$, IDA*, asymptotic analysis.
Tools

Data
Generated instances across several domains.

⑥Evaluation

Purely descriptive: the deliverable is the frontier map itself plus a predictive rule "given $(b,d,\epsilon,M)$, use solver X."

⑦What you can claim

A reproducible empirical characterization that turns an informal rule-of-thumb into a measured boundary — defensible because it reports what is, not what beats SOTA.

①The gap

No single solver wins on all NP-hard instances. Per-instance algorithm selection (à la SATzilla) routes each instance to its best solver — but it's underexplored outside SAT. Port it to a new domain.

②Mathematical foundation

For instance $x$ with cheap features $\phi(x)$, learn per-solver runtime predictors $\hat t_s(x)=f_s(\phi(x))$ and select

$$ s^\star(x)=\arg\min_{s}\ \hat t_s\big(\phi(x)\big). $$

Quality is measured against the oracle (always-best) selector via regret

$$ R=\sum_x \Big(t_{s^\star(x)}(x)-\min_s t_s(x)\Big). $$

③Method

  1. Collect a solver portfolio + cheap instance features.
  2. Run all solvers on a training set to get runtimes (with timeouts/PAR10).
  3. Train regressors/classifier; route at test time.

④Plan of action

⑦What you can claim

A portfolio that beats any individual solver on aggregate runtime — measurable, hard to get a null result if solvers are genuinely complementary.

①The gap

Everyone "knows" a better heuristic means fewer expansions, but the precise empirical relationship between heuristic error and $A^*$ work is rarely measured cleanly. Pohl's analysis predicts exponential sensitivity — test it.

②Mathematical foundation

Define per-node error $\epsilon(n)=h^*(n)-h(n)\ge0$. A classic result: if relative error $\frac{h^*-h}{h^*}$ is bounded by a constant, expansions grow exponentially in solution depth; if absolute error is $O(\log h^*)$, $A^*$ runs in near-linear nodes. Empirically fit

$$ \log N \approx \beta_0 + \beta_1\,\bar\epsilon + \beta_2\,d $$$N$ = expansions, $\bar\epsilon$ = mean error, $d$ = depth; estimate $\beta$ with CIs.

③Method

  1. Compute $h^*$ exactly on small instances; synthesize heuristics with controlled error by $h=h^*-\epsilon$.
  2. Run $A^*$; log expansions vs error and depth.
  3. Regress and report.

④Plan of action

WK 1–2Exact $h^*$ via retrograde analysis on a small domain.
WK 3–4Inject controlled error; sweep $\epsilon$.
WK 5–6Fit + report the empirical law.

⑤Requisites

Background
$A^*$ theory, regression, Pohl's heuristic-error results.
Tools
Python, statsmodels.
Data
Small solvable domains (8-puzzle, small grids).

⑥Evaluation

Goodness-of-fit ($R^2$), residual analysis, comparison to theoretical exponential prediction.

⑦What you can claim

A measured curve relating heuristic quality to search effort — robust regardless of the curve's exact shape, since ground truth is computable.

①The gap

Weighted $A^*$ trades optimality for speed via a fixed weight $w$, but the right $w$ depends on the time budget you actually have. Adapt $w$ online to a deadline.

②Mathematical foundation

Weighted $A^*$ uses $f(n)=g(n)+w\,h(n)$ with $w\ge1$. With an admissible $h$, the returned solution cost is bounded:

$$ C \le w\cdot C^\star . $$Higher $w$ ⇒ faster but looser; the bound is guaranteed, not heuristic.

Schedule $w(t)$ to decrease as remaining time shrinks, optimizing the anytime quality profile $q(t)=C^\star / C(t)$.

③Method

  1. Implement Anytime Weighted $A^*$ (improves solution while time remains).
  2. Add a controller that lowers $w$ based on elapsed/remaining time and current incumbent.
  3. Compare quality-vs-time curves to fixed-$w$ runs.

④Plan of action

WK 1–2Anytime WA* baseline at several fixed $w$.
WK 3–4Add adaptive $w(t)$ controller.
WK 5–6Benchmark anytime profiles under deadlines.

⑤Requisites

⑥Evaluation

⑦What you can claim

Better quality-per-deadline than any single fixed weight — a full curve makes a null result unlikely.

①The gap

Fuzzy controllers are interpretable but give uncalibrated confidence. Bayesian networks give calibrated probabilities. Can we compile a fuzzy rule base into a BN and gain calibration without losing interpretability?

②Mathematical foundation

A fuzzy rule uses membership $\mu_A(x)\in[0,1]$ and Mamdani inference (min–max). Map fuzzy sets to discretized variables and translate rule firing strengths into conditional probability tables $P(Y\mid X)$. Measure calibration with Expected Calibration Error:

$$ \text{ECE}=\sum_{b=1}^{B}\frac{|B_b|}{N}\,\big|\,\text{acc}(B_b)-\text{conf}(B_b)\,\big|. $$

③Method

  1. Take a known fuzzy controller (e.g. for a control/classification task).
  2. Derive a BN with matching structure; calibrate CPTs from data.
  3. Compare decisions and calibration on held-out data.

④Plan of action

①The gap

Exact inference cost in a Bayes net is dominated by the variable-elimination order; finding the optimal order is NP-hard, so heuristics (min-fill, min-degree) are used. Can RL learn better orders?

②Mathematical foundation

Variable elimination runs in time $O\!\big(n\cdot d^{\,w+1}\big)$, where $w$ is the induced width of the ordering and $d$ the domain size. The cost of eliminating order $\pi$ equals the sum of factor sizes created:

$$ \text{cost}(\pi)=\sum_{k} \prod_{v\in\text{scope}(\psi_k)} |dom(v)|. $$

State = current moralized/triangulated graph; action = next variable to eliminate; reward $=-\log\text{cost}$ increment.

③Method

  1. Represent the elimination process as a sequential decision problem over the graph.
  2. Train a policy (GNN + REINFORCE or DQN) to pick elimination order.
  3. Compare induced width / total cost vs min-fill, min-degree.

④Plan of action

WK 1–2VE engine + heuristic-order baselines.
WK 3–6Train policy with cost-based reward.
WK 7–8Benchmark on standard networks.

⑤Requisites

Background
Variable elimination, treewidth, policy-gradient RL.
Tools
pgmpy, PyTorch Geometric.
Data
bnlearn / UAI network repositories.

⑥Evaluation

Baselines: min-fill, min-degree, weighted-min-fill. Metrics: induced width, total operations, wall-clock — all exact.

⑦What you can claim

Learned orderings that reduce exact-inference cost on benchmark nets; the metric is exact so any improvement is unambiguous.

①The gap

Feature selection often ignores the theoretically optimal feature set. The Markov blanket of a target is exactly the minimal set that renders the target independent of everything else — but it's underused as a practical selector.

②Mathematical foundation

The Markov blanket $MB(T)$ = parents, children, and children's other parents of $T$. It satisfies

$$ T \perp\!\!\!\perp X \mid MB(T)\qquad \forall\, X\notin MB(T)\cup\{T\}. $$Given $MB(T)$, no other variable adds predictive information about $T$ — it is the optimal feature set.

③Method

  1. Learn $MB(T)$ via algorithms like IAMB/HITON (conditional-independence tests).
  2. Train classifiers on the blanket features.
  3. Compare to LASSO and mutual-information selection.

④Plan of action

WK 1–2Implement/wrap MB discovery (IAMB).
WK 3–4Run selectors on several datasets.
WK 5–6Benchmark accuracy + stability.

①The gap

Gibbs sampling needs convergence diagnostics, but practitioners pick one almost arbitrarily. A reproducible comparison on networks with known posteriors is missing.

②Mathematical foundation

Gibbs sampling draws each variable from its full conditional $x_i^{(t+1)}\sim P(x_i\mid x_{-i}^{(t)})$, leaving the joint stationary. The Gelman–Rubin statistic compares between-chain ($B$) and within-chain ($W$) variance:

$$ \hat R=\sqrt{\frac{\frac{n-1}{n}W+\frac{1}{n}B}{W}}\ \xrightarrow{\text{converged}}\ 1. $$

Also track effective sample size $\text{ESS}=\dfrac{n}{1+2\sum_k \rho_k}$.

③Method

  1. Choose discrete BNs where exact posteriors are computable.
  2. Run multiple Gibbs chains; record several diagnostics over time.
  3. Correlate "diagnostic says converged" with actual distance to true posterior (TV / KL).

④Plan of action

WK 1–2Sampler + exact posteriors.
WK 3–4Instrument diagnostics (R-hat, ESS, autocorr).
WK 5–6Compare diagnostic reliability vs ground truth.

⑤Requisites

Background

Tools

Data

⑥Evaluation

Diagnostic "false convergence" rate, detection delay, TV distance at declared convergence.

⑦What you can claim

①The gap

②Mathematical foundation

①The gap

②Mathematical foundation

Potential-based shaping adds $F(s,a,s')=\gamma\Phi(s')-\Phi(s)$ to the reward. Ng, Harada & Russell (1999) proved this leaves the optimal policy unchanged for any potential $\Phi$:

$$ Q^\star_{R+F}(s,a)=Q^\star_{R}(s,a)-\Phi(s). $$The optimal action ranking is preserved exactly — this is the bulletproof core.

Learn $\Phi_\theta$ from demonstrations (e.g. as a value-function estimate), then shape with the guaranteed-safe form.

③Method
